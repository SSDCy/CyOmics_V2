# Raw QC artifact durability helper — source candidate only

`RawQCArtifacts` is an internal unprivileged POSIX worker helper. No root or execution registration is configured by default. Importing the module launches no worker, service, filesystem probe, database query, R calculation or network request. The caller must already have authenticated/claimed and decoded its authoritative job; neither a model nor an `ExecutionRegistration` object proves authorization.

For one canonical job UUID, the helper walks the trusted server-supplied publish root with no-follow directory descriptors, checks private directory modes and current ownership, then opens exactly seven fixed regular single-link artifacts. It checks receipt provenance against the job and trusted execution registration, per-file/total limits, current bytes/SHA, metadata stability and final path-to-FD identity. It fsyncs the seven opened files, job directory, and publish parent, then rechecks identities, membership and sizes before returning a canonical sorted manifest/result validated by the existing job contract. A failed fsync, budget, integrity or time check returns no successful result. It does not modify artifact bytes or permissions, delete files, retry R, commit a job, or rewrite historical success.

The 30-second processing deadline is cooperative around each bounded read/fsync/metadata operation; kernel filesystem calls can block beyond it. Successful fsync calls are evidence of requested durability, not an absolute hardware/crash guarantee. The development owner can still mutate its own files or restore permissions, and races after the last observation cannot be excluded. This is not production immutability, a proof that R actually executed, or a substitute for the scientific output protocol/oracle. The larger runner receipt is private consistency evidence; only fixed public result fields are emitted.

The current helper deliberately uses the frozen v0.1/R3 execution contract. Its tests use explicitly synthetic v2 execution pins and bytes, not real R007 output claims. Actual v3 registration is pending a separately reviewed full runner source bundle including `process_policy.py`; this helper does not widen the wire contract to bypass that gate.

Filesystem validation must be run on unprivileged POSIX. Windows runs only three pre-filesystem tests and explicitly skips twelve POSIX tests. The exact source snapshot and local logs accompany the review; Root must run the prepared POSIX tests before promoting or claiming that filesystem checks passed. No real project inputs, server outputs, credentials or services are used by these tests.
