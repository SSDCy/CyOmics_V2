# Preprocessing log2 request contract v0.1

Contract identifier: `preprocessing_log2_job_v0.1`. Default `ENABLED=False`.
This module is stdlib-only, pure bytes parsing/canonicalization; it performs no
IO, route registration, DDL, queue insertion, authorization, source lookup,
R execution, result publication or feature activation.

The future proposed route is
`POST /api/v1/datasets/{id}/preprocessing-jobs?project_id=...`.
This source does not implement that route. Its client body has **exactly3** keys:

```json
{"request_id":"11111111-1111-4111-8111-111111111111","quant_family":"Intensity","parameters":{"blank_policy":"to_NA","filter_flags":{"contaminant":false,"reverse":false,"site_only":false},"imputation":"none","input_scale":"raw_nonnegative","log2":"positive_only","normalization":"none","output_scale":"log2","preset":"positive_log2_zero_na_no_impute_v1","pseudocount":0,"seed":null,"steps":["flags_filter","zero_and_blank_to_NA","log2_positive","normalization_none","imputation_none"],"zero_policy":"to_NA"}}
```

`request_id` must be a canonical lowercase UUID string, with the same plain-string
predicate as current validation.canonical_uuid. It is not generated by this
module and is not an Owner credential. `quant_family` is exactly `Intensity` or
`LFQ intensity`; no aliases, whitespace trimming, case folding or default choice.

The source parameter original is411 bytes, SHA256
`c84e77dc7c9910238356add0f78e31874ebfa3b20ad6175dae59439c3c806e07`.
It has **12**, not14, top-level parameter keys: blank_policy, filter_flags,
imputation, input_scale, log2, normalization, output_scale, preset, pseudocount,
seed, steps and zero_policy. The earlier14 count was a task-description typo,
confirmed by Root; no fields are invented to reach that count.

Only filter_flags.contaminant, filter_flags.reverse and filter_flags.site_only
may vary, and each must be a JSON boolean. Reference fixture true flags are not
defaults or an instruction to remove all flags. All8 combinations are valid;
the frontend starts allfalse and requires explicit family choice. All other
parameter values/types and the ordered five steps are exact. In particular
pseudocount is the integer0 (not false or0.0), seed is null, and normalization
and imputation remain none. No invalid-value-to-NA alternative is introduced.

The frontend callback `{contextKey, source, quant_family, parameters}` is **not**
the HTTP request body. A future host adapter must create/reuse an explicit
request UUID and copy only quant_family/parameters unchanged into the3-key body.
contextKey/source belong to host lifecycle isolation, not server authorization.
Sending that full envelope, schemaVersion, params, Owner/project/dataset/file
IDs, hashes, paths or execution values is rejected as unknown client fields.

## Pure API and canonical hashes

`request_input(raw: bytes) -> PreprocessingRequest` accepts only immutable bytes,
1..4096 bytes inclusive. JSON must be strict UTF8, no BOM, duplicate keys at
any depth, NaN/Infinity, lone surrogate, trailing second value or depth above8.
Every schema/key/type is checked; no bool/int/float equivalence is accepted.
Transport whitespace and key order are allowed and normalized, with no source
field or scientific inference. All refusals expose only a fixed RequestError
code: invalid_preprocessing_request or preprocessing_request_too_large. A future
HTTP adapter may map these to its approved input-error response after preserving
the required authentication/Owner/source-failure precedence.

The frozen slots dataclass contains request_id, quant_family, immutable named
filter_flags tuple, parameters_bytes, parameters_sha256, canonical_request_bytes
and request_sha256. The server reconstructs all accepted parameter fields from
its constants and the three validated booleans, then emits UTF8 JSON sorted by
keys with compact separators, no trailing LF, ensure_ascii=False and no nonfinite
numbers. SHA256 is computed over those actual canonical bytes. The alltrue
parameters exactly reproduce the411-byte original. `canonical_parameters(flags)`
provides the same strictly validated named-boolean reconstruction.

The request hash covers all3 canonical body keys, including request_id and family.
The parameter hash covers only the complete12-key parameter object. Whitespace
and key ordering do not change hashes; family/request UUID or flags do. It does
**not** bind Owner, project, dataset, immutable source, tool or execution. A
matching hash or caller-constructed dataclass does not prove provenance or grant
authorization. Future idempotency must be scoped to authenticated Owner/route/
authoritative source and explicit request ID; never deduplicate globally using
this unbound request hash alone. `.parameters_value()` and `.request_value()`
return detached copies and cannot mutate the frozen canonical snapshot.

## Required future server boundary

The future Owner API must independently authenticate the real subject, validate
route project/dataset, resolve and authorize the immutable SourceRef from server
records, validate source/report/family availability, and bind the approved tool,
execution registration, parent/version and normalized request. None of these
values may be taken from the body or a frontend contextKey/source assertion.
This slice intentionally creates no new SourceRef type, path loader, Owner
shortcut, execution schema, repository, SQL capability or queue implementation.
The R argv flag order is reverse/contaminant/site_only; adapters must use the
named flags rather than assuming the canonical alphabetical tuple is argv order.

The standard R base::log2 core and byte validator are separate reviewed sources.
Parsing these parameters does not execute either, convert any matrix, validate
scientific applicability, approve a sample design or mark analysis_ready.

## Source evidence

Tests use only raw synthetic JSON and the fixed public411-byte parameter fixture.
They exercise both family names across8 boolean combinations, duplicate/escaped
duplicate keys, unknown server-bindings, complete parameter/type/step rejection,
malformed UTF8/surrogates/nonfinite JSON, exact size boundary, canonical UUIDs,
immutable snapshots and canonical-hash semantics. No actual Owner, SourceRef,
R, network, filesystem or DB operation is tested or attested. Root and an
independent reviewer must approve this source before any future integration.
