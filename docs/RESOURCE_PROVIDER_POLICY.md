# 科研资源选择规范：本地优先，官方 API 补充

本规范落实项目用户于 2026-11-17 明确提出的要求，适用于 BLAST、Pfam、
SMART、CDD、eggNOG、GO/KEGG、STRING、AlphaFold、PDB、亚细胞定位等模块。
它规定后续实现和验收规则；文档存在不表示各模块的路由、任务执行器或在线接口已经接通。
机读规则见 `contracts/resource-provider-policy-v1.json`。

## 选择顺序

1. 由服务器检查已登记的本地资源、对应工具和必需索引。资源必须适用于当前
   功能、标识符及目标物种，不能仅凭存在一个同名目录判定可用。
2. 本地资源可用就使用本地数据和计算，不调用对应在线服务。版本无法核实时
   如实记录“未核实”，不能把文件修改时间当作数据库发行版本。
3. 缺少可用本地资源时，按项目的外部服务设置调用已经核实能力和参数的官方 API。
   当前项目用户已同意这种补充方式；该同意不能代替其他用户项目的外部服务选择。
4. 尚未检查本地资源时，状态为“待核实”，不能把未知直接当成不存在。权限、
   损坏或执行错误应说明原因，不能静默换源。确认为不可用后的提供方切换必须可追溯。
5. 本地“无命中”或“无相互作用”是有效结果，不等于缺少数据库，不能因此自动
   改用在线服务来寻找更好看的结果。没有适用官方 API 时显示尚不可用，不伪造接口或结果。

## 各角色责任

- 后端：维护服务器资源登记和能力级别的选择，禁止客户端指定任意路径、命令或 URL。
  同一任务固定来源和参数；处理官方服务的超时、限流、任务状态及失败，不无限重试。
- 前端：明确显示本地/在线来源、数据库和工具版本（未知也显示），以及在线发送的是
  蛋白 ID 还是序列。优先只发送功能所需的 ID 或选中序列，不上传整个定量表或项目。
- 测试：分别验证本地可用、确实缺失、待核实、物种不匹配、有效无结果和官方服务失败。
  用同一固定输入检查标识符、序列哈希、坐标和来源；版本/方法不同不得声称结果必然相同。
- Root：审核资源证据和实际实现，再整合交付；单位测试、真实工具测试、平台联调及用户
  验收分别记录。资源检查只读限定路径，不遍历备份或生产源码，不改旧生产数据库。

## 模块约束

- Pfam：当前本地原始 HMM 库已经用于一次真实 HMMER 测试，后续优先复用。
  必须记录 hmmsearch/hmmscan 等实际方法和阈值，不能把候选结构域结果说成完成了
  PfamScan 的全部后处理或已经验证蛋白功能。
- STRING：检查所需物种的网络、对应版本及标识符映射；仅有序列库不能代替相互作用边表。
  不得把近缘物种网络直接标记为当前物种。能力可分别选择来源，例如网络本地可用时仅为
  缺少的标识符映射使用官方 API，并分别记录来源，不能整项改成在线计算。
- AlphaFold/PDB：本地结构与用户蛋白的对应关系必须核实，保留序列、链和来源信息。
  找到相似序列或结构条目，不代表就是该原始蛋白的结构。
- 其他模块：下载资源、检索元数据、运行预测/注释是不同能力，分别核实；存在网页或
  数据查询 API 不等于存在可以提交序列进行计算的官方任务 API。
- 科研统计及图形继续使用已验证的 R 包或官方 R 函数。资源提供方选择不会改变该要求。

## 可追溯记录

记录所选功能、输入版本/ID/序列哈希、物种及映射方法、提供方和选择原因、数据库名称、
发行版本及核实状态、文件指纹、计算工具及版本、参数、时间、结果状态。在线调用另记
官方服务身份及版本、任务 ID（若有）、发送范围。不得记录凭据或把真实用户数据提交到公开 Git。
