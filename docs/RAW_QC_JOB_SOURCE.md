# 原始质控任务存储源码候选

本切片保存不可变原始文件版本、请求身份、执行版本与四种任务状态。HTTP 边界已有默认关闭的源码与离线验证；独立 R worker、产物下载和实际启用仍未完成；它不表示网站可以执行质控。

`007_private_raw_qc_jobs.sql` 是待应用的开发库提案。没有提交该迁移，不可自动执行或重复运行既有 001–006。对固定开发 PostgreSQL 17 的四次合成事务测试（R3 与 v3 各两次）已实际验证有效入队/领取、Owner 隔离、窄权限、严格数值及产物顺序验证、CAS 和终态保护；四个事务均回滚，新增角色、表、合成数据及父表权限改变均未保留。这不是并发、真实账号 HTTP 或上线证明。

执行注册默认未配置。源码的前端、后端与 SQL 已统一为 `raw_qc_limits_v3` 的完整 14 字段预算与摘要，版本信息见 `RAW_QC_EXECUTION_V3.json`。历史 v2 tiny 失败证据保留；v3 已通过两族 tiny 和两份真实 TXT 的四次独立原始质控运行，28 个结果文件经独立核对。运行验证采用受审的平面脚本布局，源码包布局尚未实际执行 R；这些结果不表示网站任务已启用。完整 runner 源码包注册、worker 接线和真实账号端到端验证仍待完成。后续配置版本变化必须同时更新注册验证与 SQL，不能仅修改摘要使其通过。

范围仅原始 QC，区分空值和原始零值；不要求样本设计先确认，不进行过滤、归一化、填补、PCA 或差异分析。科学脚本及绘图依照既定 R 规范。

离线合成测试：在 backend 目录以独立解释器运行 `python -B -m unittest discover -s tests -p test_raw_qc_contract.py` 与 `test_raw_qc_repository.py`。测试注册、数据和数据库模型均为合成，不连接实际服务。

HTTP 源码提供三个操作：POST 入队、GET 按已知 request_id 精确恢复、GET 按 job_id 查询状态。返回单个严格校验的任务对象；POST 非终态为 202，终态重放为 200，GET 为 200。未注入服务端仓库时返回 503；不能通过客户端参数启用或传 Owner、矩阵、路径、执行配置。

提交已进入仓库之后的协议或响应不确定性返回 submission_unknown，前端应保留原 request_id 只读回查。已确认的仓库拒绝保留原码，不重复 POST。此 HTTP 切片经 13 项作者测试和 23 项独立/返修边界测试验证；使用合成 Authority/数据库与内存 ASGI，不代表真实认证、BFF、跨用户 HTTP、worker 或科学 E2E。
