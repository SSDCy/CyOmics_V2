# Fixed bound-source RPC reader — source only

`WorkerBoundSource(pool=None, bound_raw_factory=None)` is disabled without both trusted server dependencies. It does not import an executor, open sockets on import, inspect resources, authenticate a caller, or create a worker. The actual pool's function-only role and connection configuration remain a live integration gate; a Python object does not prove those grants.

`load_bound_source(job_id, attempt_id, budget)` accepts only canonical UUID strings and executes one fixed parameterized RPC projection: `SELECT source_json,execution_json,content FROM cyomics_app.raw_qc_bound_source(%s,%s)`. It uses the existing Budget/abort/release conventions in a dedicated read-only transaction, with transaction-local empty identity and statement/lock deadlines. It fetches twice to reject more than one row. There are no direct parent-table reads, Owner arguments, configurable SQL or endpoints, writes, retries or cache. No SQL migration or privilege change is needed.

Source/execution JSON is bounded before parsing, strictly decoded and checked by the existing source/execution contract, then canonically reparsed into fresh ordinary dictionaries. The current reviewed v3 support layer supplies eleven source keys and eight execution keys. A future mismatched contract is not bypassed here. Content is bytes or a bounded contiguous one-dimensional byte memoryview copied into bytes; size and actual SHA must match source. The exporter separately checks parser-derived header, rows, columns and selected-column digest; this loader does not fabricate dataset rows, timestamps or parser reports.

The injected factory is called with exactly five keywords: job_id, attempt_id, source, execution, content. Its result must be a frozen dataclass with exactly those fields and unchanged values. This is a structural seam, not authorization. The ordinary nested dictionaries are deliberately not recursively frozen so that existing validators/exporters can accept them. Every load parses fresh objects; modifying an old return cannot poison the database or later responses. The caller must compare source/execution against its claimed job and use the exporter's synchronous canonical snapshot before filesystem preparation.

Every assigned connection is synchronously aborted/closed before release, including successful reads, so a preexisting session identity is never returned for reuse merely because the read-only transaction committed. If teardown cannot confirm closure, the socket is withheld from the pool; this can consume a pool slot and requires caller/operator recovery rather than retry or unsafe reuse. Late acquisition after timeout is similarly closed before release, with no raw callback exception logging. Cancellation remains cancellation when cleanup succeeds. Failures expose fixed sanitized codes and no content, paths or credential text. COMMIT here has no job mutation and is not reported as successful job submission.

Seventeen in-memory SQL-shaped tests cover configuration/UUID/deadline gates, exact read-only RPC, absence/multirow, strict JSON/UTF8/caps, memoryview copy, SHA/size, detached objects, factory mutation, dirty transactions, failures/teardown, cancellation and late acquisition. These are not PostgreSQL role/RLS, real bytea, server connection, exporter, runner or E2E tests. No actual database, R, Auth, service, research file or shared repository has been modified.
