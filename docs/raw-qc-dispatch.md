# One explicit raw-QC server action — source only

`await dispatch_once(config=None, action='run_once', expected_attempt_id=None, expected_job_id=None)` is a server async callable. No CLI, process manager, route, daemon, loop, SQL, credential channel or runtime is created by importing this module. Default None returns off before platform checks or POSIX imports. It does not register anything globally or authorize a project.

An exact trusted `Config(runtime, roots, expected_uid)` is required. `runtime` must be the existing factory's exact `raw_qc_runtime.Config`; `roots` the existing `WorkerRoots`. The explicit UID must match the factory UID, and its three execution roots must equal the matching five-root structure. The existing roots/factory perform their regular UID, permissions, pin, no-follow and native checks. No path/URL/Owner/password/DB-endpoint/limits parameter is accepted by this callable.

`run_once` permits no expected IDs: they are not a claim selector. `ack_confirmed` requires two canonical UUIDs and calls only `acknowledge_confirmed(expected_attempt_id=..., expected_job_id=...)`. Invalid actions/ID combinations return fixed errors before configuration I/O. This function is a general-queue single invocation; specifying an imagined CLI target cannot guarantee which queued job `claim` selects. A first-integration guard must independently establish the permitted queue/fixture state before invoking it.

Assembly deliberately loads only the factory and checkpoint configuration modules first. It verifies roots and calls the existing factory, which validates the complete approved sibling bundle before importing native runner code. Only then are WorkerOnce, Pool, repository, loader, artifacts and input exporter imported. The ordinary runner and registration types, roots, script/executable pins, entry kind, R version and resource profile/hash are checked together before Pool construction. Whole-backend release/source approval remains an external trusted startup gate; Python object/file checks are not imported-memory attestation.

The fixed real wiring uses WorkerPool(PoolConfig(expected_uid)), RawQCWorkerRepository(pool), WorkerBoundSource(pool=pool,bound_raw_factory=BoundRaw), RawQCArtifacts(published,registration), InputExporter(inputs), the five roots and existing Budget class. No app/admin pool or preverified Owner is injected. The worker Pool itself retains its fixed endpoint, server-only lazy secret reader and function-only-role provisioning gate. No new credential read path, role or migration is introduced here.

Exactly one worker method is awaited. Recovery/idle/busy/unknown/refusal are returned; there is no implicit ACK, repeat claim, transition retry, next task or R rerun. ACK requires the existing confirmed state and lock and retains its current read/fsync/history semantics. This module does not change journal formats, delete state or clear quarantine. Its source interface assumes the separately reviewed ACK slice is present in the deployed release.

Return is frozen `DispatchOutcome(action,status,reason,attempt_id,job_id,teardown)`. Action/status/reason are fixed enumerations; UUIDs are canonical or None. Unexpected objects, messages, paths and exceptions are replaced with fixed off/unknown reasons. A confirmed success requires a permitted terminal reason and both IDs; idle cannot carry IDs; acknowledged must match both supplied IDs and its fixed reason. `confirmed/failed` remains a confirmed failed job, not scientific success.

Teardown is a separate `confirmed` or `unknown` field. R1 marks setup unconfirmed immediately before the potentially descriptor-owning `roots.verify()` and `create_runtime()` calls. Any exception/cancellation before both return normally keeps teardown unknown even though no Pool exists; a fixed off/configuration-unavailable business result is retained. Normal completion clears only this setup-stage marker, then existing Pool and pending-task checks still apply. Exact configuration type/UID/root-correspondence rejections precede that stage and remain clean. The fixed configuration/worker module imports have no resource-acquiring startup probes under their source contracts; a pure import error before setup or after its normal completion does not itself assert a setup leak. This model is not native descriptor attestation. `pool.close()` returning None is not evidence of closure: this wrapper tests the current reviewed Pool's `_closing is True`, `_held is False`, `_lease is None` and `_uncertain is False`. This is intentional coupling to that fixed Pool revision, covered by tests and requiring review if its contract changes. One scheduling turn is allowed, then any newly pending task conservatively makes teardown unknown. It does not cancel, await indefinitely or claim ownership of unrelated tasks; no task names/handles are exposed. A close exception is consumed without logging and produces unknown teardown even if state looks clean.

Already confirmed business state is preserved when teardown is unknown. Controllers must inspect both fields and stop on unknown; neither a confirmed status alone nor a fresh Pool/Runner instance proves prior resource disposition. The caller must not reinvoke this function after unknown cleanup until separate review establishes closure. There is no persistent global quarantine manager here, and no automatic replacement/retry. Existing unresolved checkpoints still prevent R resumption; they are never reset by this wrapper.

The callable requires Linux/POSIX, matching positive real/effective UID and a dedicated single MainThread. It also refuses before configuration I/O when another live asyncio task is already present: it cannot assume that pre-existing work is known safe or build a replacement pool alongside a previous unknown task. The caller should directly await it in its sole foreground task; shared ASGI loops and task-wrapping timeout patterns do not satisfy this exclusive-loop precondition. It never cancels those external tasks. R remains synchronous in that thread, outside ASGI or a thread pool. Existing per-RPC Budget, R resource limits and artifact budgets apply inside their existing components. This wrapper does not implement an overall process timeout or solve `asyncio.run()` shutdown waiting for a cancellation-ignoring task. Foreground event-loop/OS lifecycle and any unknown-process disposition stay with the independently reviewed outer entry; no hard-shutdown guarantee is inferred.

The original seventeen synthetic methods are retained unchanged and cover default inertness, pre-I/O refusals, factory-before-worker import order, exact assembly arguments, type/root/pin/limits mismatches, one-action-only behavior, recovery, ACK unknown, contradictory result rejection, cancellation/exception sanitization, pool close failure/stale state and existing/newly pending tasks. Eight R1 stage-boundary tests add cancelled setup, pure import/pre-I/O refusal boundaries and normal setup completion; seven unchanged independent QA assertions are rerun separately. Dependencies are local private mocks; no production dependency override is exposed. These tests run on Windows and do not establish real POSIX, bytea/psycopg, LOGIN/SCRAM, credentials, R or Owner E2E. No actual secret/server/SQL/service operation or shared repository change occurred.
