# limma_core_v0.1 — source-only scientific contract

This candidate is an unregistered scientific core. It supplies no Owner/JWT check, filesystem sandbox, version persistence, HTTP, worker, runtime profile, scheduler, cryptographic input validation or trusted dependency discovery. No scientific execution occurred during authoring. Installation/loading of isolated R 4.6.1 / limma 3.68.5 / statmod 1.5.2 is separate evidence, not a computational test.

## Trusted invocation and lineage prerequisite

Future reviewed executor calls a pinned Rscript with `--vanilla limma_core.R MATRIX DESIGN PRESET OUTPUT_DIR`. Exactly four server-selected local paths; never expose these as client paths or use user names in shell/formula code. OUTPUT_DIR is a new private directory prepared by that executor. The five output names below must not already exist. Writes are not atomic and no fsync/publication guarantee is made here; an exception can leave partial staged outputs. The future executor must own timeout/cancellation/resources, exact library/native/script pins, fixed allowlist, SHA/length checks and immutable publication. This source defines no new effective execution profile, business quota or automatic retry.

Before invoking R, trusted platform code must bind the actual bytes and parsed dimensions to: Owner/project/dataset, quant_family, raw source byte SHA/parser/config/report, raw-QC job/execution/result-manifest SHA, immutable processed version and its parent/params SHA, matrix/rowmap/all four masks SHA, selected source columns, globally confirmed design/version/design-SHA/record-SHA, and one explicit immutable contrast snapshot. Same IDs or claimed SHA alone do not prove this chain. R does not calculate SHA256 or independently establish those claims. Hash all five outputs and the ordered test-set bytes afterward and attach them to that chain. No client DTO may replace this gate. Do not substitute latest-head design or infer confirmation from a single confirmed row. The design file carries only internal keys; original column ordinal/name/label/group/condition/replicate provenance stays in the externally bound immutable sample design.

Only an upstream **confirmed log2** matrix is accepted: log2 of positive raw values, original zero and original blank become NA; pseudocount=0, normalization=none, imputation=none. These transformations are NOT performed by this R core and the preset is not proof they occurred. Upstream original_blank/original_zero/working_NA/imputed masks must match shape, imputed mask must be all false, working_NA must correspond to exactly the missing input cells. The three-flag preprocessing preserve/none matrix is original scale and cannot be fed directly to this core. Do not apply log2 a second time. A numeric **0 or negative value in the log2 matrix is a valid observation**, not an original zero/missing value. No fill or imputation is performed.

## Exact input files (UTF-8 TSV, LF or CRLF)

Tables use literal tabs, no quoting/escape or comment semantics; values cannot contain tab, CR or LF. No duplicate/extra/reordered headers. Structural/schema/design/preset failures stop the whole calculation; invalid matrix numeric tokens are retained as invalid rows instead. R imports every column as character before controlled conversion, preserving Protein IDs including spaces, quotes, repeated IDs, semicolon-separated groups and blank IDs. Source row ordinals must be canonical decimal integers 1..9007199254740991, strictly increasing, unique and already in retained original source order; gaps are allowed. They identify source rows, not protein-group deduplication keys. Matrix dimensions are supplied by the upstream version; this core never invents additional rows.

1. MATRIX: `source_row_ordinal`, `protein_ids_raw`, `s1` .. `sN`. Each numeric cell is exactly `NA` (the sole missing token) or a finite decimal/scientific numeric token, with no surrounding whitespace. Empty, NaN, Inf and arbitrary tokens make the entire source row not_testable, not a silently ignored observation. Finite log2 zero/negative values remain observed. There are N columns in original included-column order.
2. DESIGN: `sample_key`, `group_key`, `replicate_key`, `replicate_type`, `confirmed`. Exactly one row for each `s1..sN` in the same order. N=4..64 is this candidate's technical input bound, **not an approved platform sample quota**. Every group is g1/g2, each group has >=2 samples, biological=true is represented by literal replicate_type `biological`, confirmation is literal `true`. Replicate keys match `[A-Za-z0-9_-]{1,64}` and are unique within group. The trusted mapper assigns baseline g1=denominator, g2=numerator; biological independence is an explicit upstream assertion, not something code can establish from distinct strings. No technical, paired, batch, repeated-measure, weight or block design is supported. Excluded source columns/reasons belong in the upstream lineage, not this two-group fit.
3. PRESET: ordered `key`, `value` rows exactly as fixture preset.tsv. Fixed values: schema_version=limma_core_v0.1, input_scale=log2, upstream_transform=positive_log2, upstream_zero_blank=NA, pseudocount=0, normalization=none, imputation=none, replicate_type=biological, design_confirmed=true. contrast_id is internal `[A-Za-z0-9_-]{1,64}`. numerator/denominator must be the distinct pair g1/g2. Baseline is g2−g1; explicit reversal changes only contrast_id/numerator/denominator and keeps design/sample mapping unchanged. No user group name is parsed as a formula, coefficient name or command.

## Model and row eligibility

Design is a numeric N×2 one-hot matrix built by equality to g1/g2, no intercept; QR rank must be 2. Contrast is one explicit numeric ±1 column with internal name c1. Before fitting, each row must contain no invalid numeric token and >=2 finite observations in each group. Literal NA is omitted by limma, never replaced. Fit all these eligible rows jointly using `limma::lmFit(method='ls',ndups=1,spacing=1,weights=NULL,block=NULL,correlation=NULL)` with this explicit design. Duplicate protein IDs are independent source rows; ndups=1 does not collapse them. Retain only fit rows with positive finite residual df, finite nonnegative residual sigma, finite coefficients and positive finite unscaled standard errors for moderation; other rows remain in full output with invalid_fit_or_residual_df and NA statistics. Zero sigma is passed to limma, not replaced by a custom variance correction.

Use `limma::contrasts.fit(contrasts=<numeric column>,coefficients=NULL)` then `limma::eBayes(proportion=0.01,stdev.coef.lim=c(0.1,4),trend=FALSE,span=NULL,robust=FALSE,winsor.tail.p=c(0.05,0.1),legacy=NULL)`. These are frozen proposal parameters including the NULL legacy selector, not a claim that a future limma release chooses the same algorithm. The exact package version is required; no altered defaults, robust fitting, paired model, weights, trend, TREAT or extra covariate. One-hot group coefficients are orthogonal, including row-specific missingness, avoiding a nonorthogonal contrast approximation. No custom statistic/P-value/empirical-Bayes function is implemented. After moderation, rows with nonfinite coefficient/AveExpr/t/df/P, nonpositive df or P outside [0,1] remain not_testable with NA statistics. n_fit records observations supplied to lmFit, even if later rejected; pre-fit rejected rows have n_fit=0. Since imputation is none, n_obs equals the finite observed input count, and n_fit equals n_obs for fitted rows.

Use **once per contrast** `stats::p.adjust(P.Value[tested],method='BH',n=m)`, where m is every final testable finite-P row. No DEP fold-change/P threshold, top-k/topTable, identifier deduplication or annotation filter changes this family. test-set.tsv records all source rows in original order and their membership; future binder records its actual byte SHA, m and method. `FC=2^log2FC` is a geometric-scale ratio, not a ratio of raw arithmetic means. Overflow or numeric underflow yields FC=NA and FC_reason=overflow/underflow while retaining a valid log2FC/t/P/BH test. Missing/not_testable numbers serialize as NA, never fake 0 or P=1. TSV NA must become JSON null in a future DTO, never the string NA or nonfinite JSON.

## Exact five outputs and disposition

- results.tsv full original retained source rows, unsorted by significance: `source_row_ordinal/protein_ids_raw/contrast_id/test_status/reason/log2FC/FC/FC_reason/AveExpr/moderated_t/df_residual/df_total/P.Value/adj.P.Val/n_obs_num/n_obs_den/n_fit_num/n_fit_den`. reason is a fixed semicolon-ordered code list (invalid numeric first, insufficient numerator then denominator); later fit/result failures use one fixed code. FC_reason is independent of test validity.
- method-audit.tsv ordered key/value data with all method arguments, direction, scope, eligible/testable/BH m, version and warning audit. Warning text is not logged: each caught limma warning adds the fixed limma_warning_review_required code/count, and forces exit4. This is a review-required computation, never publishable success.
- sample-audit.tsv input design plus 1-based matrix_column_ordinal and numeric contrast_weight; no reordering.
- test-set.tsv all source ordinals, included_in_BH boolean, P.Value, status and fixed reason.
- R-session.txt actual UTC timestamp/sessionInfo/package/runtime data; no synthetic session golden is supplied.

Exit0=COMPUTED_CANDIDATE only if some rows are testable and no warnings; it is not authorization to publish. Exit3=NO_TESTABLE_ROWS, still full audit/full rows, not analyzable success. Exit4=REVIEW_REQUIRED_LIMMA_WARNING, full staged tables subject to scientific review. Exit2=whole calculation error, fixed stderr limma_core_failed, no valid successful result; partial output files may exist. No auto retry, deletion or recovery. Scientific method choice and application thresholds await user/Root acceptance.
