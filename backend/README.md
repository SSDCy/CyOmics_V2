# 私人项目与原始 TXT API 源码

此目录保留已审源码的程序门槛和固定依赖目标。默认工厂/CLI不启动真实服务，不能通过浏览器参数打开上传或改变身份。实际运行配置、凭据及已有服务器启动脚本没有收入公开库。

范围包括私人项目列表/创建/详情、原始 TXT 存储校验及查询接口、Owner 事务与 RLS 配合源码、合成后端测试。上传成功只代表原始字节保存，不代表解析、计算或科研分析完成。

迁移源码的依赖顺序为 `001_cluster_bootstrap.sql` → `002_database_owner_projects.sql` → `003_private_raw_uploads.sql`。本次补入的 001/002 与既往独立业务库迁移收据中实际输入的字节数及 SHA-256 一致；没有重写 schema，也没有执行迁移。文件头的 `REVIEW DRAFT`、`NEVER EXECUTED` 是最初草稿阶段留下的注释，为保持原执行版本逐字节一致而保留，不代表历史收据未执行，也不代表本轮已执行。

这些脚本只面向将来经过单独核准的、全新隔离的 PostgreSQL 17 业务集群。集群须明确配置 `cyomics.cluster_kind=businessdev`，使用受控的本地 Unix socket 与 postgres 身份；001 要求连接维护数据库 postgres，且除系统数据库、系统角色及 postgres 外保持空白。取得这些 SQL 不会创建集群、配置 socket/身份映射或提供运行配置，不能用于认证集群或其他已有数据库。

001 先在事务内创建最小权限角色，再在事务外执行 `CREATE DATABASE`，随后提交数据库 ACL 事务。因此不能使用 `psql -1` 或把整个文件包进单一事务；后续失败可能留下已提交的角色或关闭连接的新数据库。脚本要求目标角色、数据库不存在，002 要求业务 schema 尚未建立；这不是可重复执行的升级脚本。遇到已有对象或部分成功必须拒绝继续并单独审查，不能自动重试、删除对象或放宽约束以适配现库。

002 需要重新连接独立业务数据库，验证集群标记、所有者、角色属性及权限后建立 `cyomics_app`、workspaces 与 projects。两个表均启用并强制 RLS；运行账户仅获必要的 schema/function 使用、SELECT 和限定列 INSERT 权限，不获 UPDATE、DELETE、DDL 或父角色成员资格。身份由每次事务内设置的用户标识配合策略约束，不能把该标识当作认证替代品。

003 依赖前两步的角色、schema、工作空间和项目表，补充私人原始 TXT 的临时 bytea 存储结构；它同样有目标集群及已有结构检查，不能先在空库执行。001/002 不包含密码，凭据、安全配置与实际运行条件需另行供应和核准，不收入该公开源码库。

本次只确认迁移来源字节、顺序与源码防误运行边界，没有完成全新安装、真实迁移、RLS 或运行账户连接验证。`docs/SOURCE_BASELINE.json` 继续保留初始公开提交的历史基线；本次 README 的有意变更及新增迁移由独立审查差异记录，不通过改写历史清单掩盖变更。

`requirements.txt` 记录既有验证环境的十个核心包版本，不是完整传递依赖锁。该后端此前使用 Python 3.12.16；全新安装、全套 POSIX 权限用例和数据库初始化仍需单独验证。测试中的注入对象及 JWT 都为合成用例，不能替代真实身份验证或端到端验收。
